# 02 专业能力矩阵

> 状态：待评审。**当前所有专业的所有能力均为"未开发"**，本文给出的是判定规则和 V1.0 目标。

## 1. 能力项与判定规则

能力状态由系统根据证据自动计算，写入 `profession_capabilities`，不提供手工改为"可用"的入口。能力按（专业 × 地区）分别计算，V1.0 地区为山东省。

| # | 能力项 | 判定为"可用"的证据 |
| --- | --- | --- |
| 1 | 专业已建立 | 专业分类、子分类存在，适配器已注册并通过接口自检 |
| 2 | 清单识别 | 该专业至少 1 个真实清单样本识别后与原件逐项核对通过 |
| 3 | 定额数据库完整 | 已登记定额版本及授权信息；导入校验通过；章节覆盖率达到该版本目录的 100%（部分导入显示百分比和缺失章节） |
| 4 | 计价规则完整 | 费用规则集、舍入策略、不可竞争费用规则已录入并由数据管理员对照依据文件复核签字 |
| 5 | 资源价格可用 | 该专业定额涉及的资源在指定地区和基准期的价格覆盖率（显示百分比） |
| 6 | AI 定额匹配 | 3、4 可用，且匹配指标在测试样本上达标 |
| 7 | 自动组价 | 3、4、5、6 可用，且计价体系引擎已注册并通过对照测试 |
| 8 | 人工组价 | 适配器已注册。无定额数据时仍可用：人工录入补充子目和资源进行计算，结果标注"非定额依据" |
| 9 | 报价审核 | 通用检查可用；专业特有检查已实现的另行标注 |
| 10 | 报价导出 | 清单一致性检查可用，且至少一种导出模板可用 |
| 11 | 真实项目验证 | `profession_test_cases` 中有通过的样本，显示样本数量 |

## 2. 专业总体状态

由上述 11 项推导：

| 状态 | 条件 |
| --- | --- |
| 已开发并通过真实项目验证 | 1–10 可用，且 11 达到规定样本数 |
| 支持自动组价但需人工复核 | 7 可用，11 未达标 |
| 支持 AI 辅助组价 | 6 可用，7 不可用 |
| 已开发但仍需完善数据 | 1、8 可用，3、4、5 部分完成 |
| 支持人工组价 | 1、8 可用，3 或 4 为空 |
| 数据缺失 | 1 可用，3 和 4 均为空（与"支持人工组价"同时显示） |
| 暂不支持 | 适配器未注册 |

## 4. 一个需要说明的现实约束

B–I 族是行业主管部门发布的计价体系，费用构成和取费程序与 A 族差异很大，每一族都需要单独开发计价体系引擎并录入规则。在没有该族定额数据和真实项目对照的情况下，引擎可以按公开的编制办法开发，但**无法验证**，因此状态只能停在"支持人工组价"或"已开发但仍需完善数据"，不会显示为可自动组价。

建议贵司按实际投标业务量给 B–I 族排优先顺序，优先取得业务量大的专业的数据和样本。
